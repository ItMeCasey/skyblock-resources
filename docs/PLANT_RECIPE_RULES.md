# Rules for the plant and block recipes of other mods

How the recipes under `recipe/plants/<modid>/` and `recipe/compat/<modid>/` were made for the 26.1.2 mods, so the same rules apply to every version. The files are plain data: they are written once per version from the mods loaded in a dev environment, committed, and never regenerated by the build.

## Where files go

- 26.1.2 recipes live in `common/data/skyblock_resources/recipe/...` (shared by all builds; each has a `neoforge:conditions` load condition that the build transform rewrites per loader).
- Recipes for a mod on another Minecraft version live in `overrides/<mc>-<loader>/data/skyblock_resources/recipe/...` (for example `overrides/1.21.1-neoforge/...`). On 1.21.1 and 26.1.2 Forge and NeoForge have zero compatibility: different mod builds and sometimes different ids, so each loader is scanned with its own mod builds and has its own folder; never reuse one loader's scan for the other. 1.20.1 is the exception: NeoForge forked from Forge there, so Forge builds run on NeoForge 1.20.1 and one scan serves both; put 1.20.1 mod recipes in `overrides/1.20.1/`. Write them in the 26.1.2 JSON format with `neoforge:conditions`; the transform converts them for the loader.
- Never edit a `common/` file to fix one version. If a shared file is wrong for a version, replace it or add a `.delete` marker in `overrides/<mc>/` (fixes that are true for the Minecraft version) or `overrides/<mc>-<loader>/` (anything about mods).

## What to scan

Load the mod in a dev environment of that version, then list every registered item whose block is a plant:
- **Trees:** items whose block is a sapling with a known tree configuration (a tree feature). The tree drops come from rolling the trunk block's loot table once and the leaf block's loot table 20 times (the average leaf count), 400 to 600 rolls, summarized per item as the smallest and largest total and the chance it dropped at all.
- **Crops, flowers and other plants:** vegetation blocks (crops, flowers, mushrooms, lily pads, cactus-like plants). The drops are the block's own drops at full growth (use `BlockState.getDrops` so blocks that override `getDrops` work).
- **Resource blocks:** raw natural blocks only: dirt-like soils, sands, gravels, clays, natural stones and cobbles. Not crafted blocks (bricks, slabs, stairs, polished or chiseled variants), ores, storage blocks, decorative blocks, or machines.

## What to leave out

- One recipe per seed or sapling. If a produce item only works by borrowing a seed's plant (wheat from wheat seeds, a Croptopia vegetable from its seed), skip the produce item and keep the seed.
- Farmland blocks and any block that is a soil rather than a plant.
- Blocks that are decoration, not plants: vines, hanging vines, leaf litter, roots, grass, ferns, bushes whose loot is wheat seeds (berry bushes that roll vanilla grass loot), `*_natural` worldgen variants, fruit "crop" leaf blocks that are not obtainable items.
- Any plant whose sampled drops are empty. Remove `minecraft:air` and zero-amount entries from every drops list.
- Mods that only change worldgen (no registered items): nothing to write.

## File format and naming

Trees (3 files per sapling, soils dirt, farmland, improved), `recipe/plants/<modid>/trees/<item>_in_dirt.json`, `_in_farmland.json`, `_in_improved.json`:

```json
{
  "neoforge:conditions": [ { "type": "neoforge:mod_loaded", "modid": "<modid>" } ],
  "type": "skyblock_resources:tree_drops",
  "sapling": "<modid>:<sapling>",
  "soil": "#skyblock_resources:base_soils",
  "generator": "#skyblock_resources:tree_generators",
  "outputs": { "id": "<first drop>", "count": 1 },
  "drops": [ { "id": "...", "min": 1, "max": 4, "chance": 0.378 } ],
  "duration": 1000,
  "category": [ "misc" ]
}
```

The soils are `#skyblock_resources:base_soils`, `minecraft:farmland`, and `#skyblock_resources:improved_soils`. Crops, flowers and seeds (one file, `recipe/plants/<modid>/crops/<item>_in_dirt.json`): type `skyblock_resources:crop_drops`, field `seed`, soil `#skyblock_resources:crop_soils`, generator `#skyblock_resources:crop_generators`.

- `max` is left out when equal to `min`; `chance` is left out when 1; chance is rounded to 3 decimals.
- The condition lists the plant's mod and every other non-`minecraft` mod that a drop comes from.
- `outputs` is the first (most common) drop, count its minimum.

Resource blocks, `recipe/compat/<modid>/<tier>_<block>_generation.json`:

```json
{
  "neoforge:conditions": [ { "type": "neoforge:mod_loaded", "modid": "<modid>" } ],
  "type": "skyblock_resources:resource_generator",
  "generator": "skyblock_resources:<tier>_generator",
  "resource": "<modid>:<block>",
  "output": { "id": "<modid>:<block>", "count": <count> },
  "duration": <ticks>,
  "category": [ "misc" ]
}
```

| Tier | Count | Duration |
|---|---|---|
| wooden | 2 | 300 |
| stone | 4 | 200 |
| iron | 8 | 150 |
| diamond | 16 | 100 |
| netherite | 64 | 40 |

Soils (dirt-like blocks) get all five tiers. Sands, gravels, clays and stones start at the stone tier. A block that only exists in the Nether or the End starts at netherite.

## Checks

- The headless self-test (`gradlew runGameTest`) must still pass, and its drop-recipe check must report no recipe without drops.
- The server log must show no recipe parse errors for `skyblock_resources`.
- Spot-check a few files against the mod's real loot (a tree should list its log, usually its sapling, sticks, and any fruit).
