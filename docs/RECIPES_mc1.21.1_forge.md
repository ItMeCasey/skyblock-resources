# Recipes for other mods: Forge 1.21.1

Files: `overrides/1.21.1-forge/data/skyblock_resources/recipe/{plants,compat}/<modid>/...` (464 files). Written once from a scan of the Forge builds, committed as plain data, same rules as `docs/PLANT_RECIPE_RULES.md`. Nothing here was taken from the NeoForge 1.21.1 scan.

## Method

- Scratch copy of `versions/mc1.21.1/forge` under `%LOCALAPPDATA%\Temp\skyres-scan-forge-1.21.1\proj` (the repo project was not touched, no scanner is in it, no `eula.txt` was created or edited, game test server on port 8913).
- Mods loaded (Modrinth, loader `forge`, Minecraft 1.21.1): Biomes O' Plenty 21.1.0.14 (+ GlitchCore, TerraBlender), Regions Unexplored F-0.5.6.1 (+ TerraBlender), Oh The Biomes We've Gone 2.6.3-Forge, mod id `biomeswevegone` (+ CorgiLib 5.0.0.10, GeckoLib 4.9.3, Oh The Trees You'll Grow, TerraBlender). Terralith and Oh The Trees You'll Grow have no items.
- A scanner on `ServerStartedEvent` listed every item of the three mods (2091 items). Trees were grown for real (`SaplingBlock.advanceTree` on a dirt, then sand, platform, single then 2x2), the trunk and leaf blocks found in the result, then trunk loot once plus leaf loot 20 times was rolled 500 times (min, max, chance per item, tool empty). Plants were sampled with `BlockState.getDrops` at full growth, 500 rolls.
- Files were generated by a script kept in the scratch directory, then checked: no air, no zero amounts, first drop equals `outputs`, no duplicate recipe keys across `common/` and this folder.
- A generated file identical in content to the existing `common/` recipe (same plant, same soil, same drop ids) is not written again: 109 files. Nothing in `common/` for these mods had to be replaced or deleted beyond the `.delete` markers `overrides/1.21.1` already has (BOP marigold, origin dandelion, origin rose, purple wildflowers, origin oak sapling: those items do not exist in BOP 1.21.1).

Soils for crops: dirt `#skyblock_resources:crop_soils` (`_in_dirt`) by default; cacti and glow canes use `sand_soils` (`_in_sand`); lily pads and the sea-grass like hyacinth bloom use `minecraft:water_bucket` (`_in_water`); mushrooms use `mycelium_soils`; the seven Nether plants of RU use `nether_soils` (`_in_netherrack`).

Resource blocks: soils (peat, sandy_dirt, lush_dirt, ashen_dirt) get all five tiers; sands, stones and cobbles start at stone; cobalt_obsidian only at netherite. BWG sands: black, white, blue, purple, pink, windswept. BWG stones: dacite_cobblestone, white_dacite_cobblestone, red_rock, rocky_stone (plain dacite and white dacite drop their cobblestone, so only the cobblestone is a recipe, like vanilla stone).

## Skipped mods (no usable Forge 1.21.1 build)

- Firmalife: the Modrinth entry is tagged forge and neoforge, but the jar (`Firmalife-NeoForge-1.21.1-3.0.3.jar`) only has `neoforge.mods.toml`, and it needs TerraFirmaCraft, which has no Forge 1.21.1 build.
- Allthemodium (Modrinth 3.0.1 tagged forge): its jar only has `neoforge.mods.toml`.
- Croptopia, Twilight Forest: CurseForge only, no Forge 1.21.1 build found (Croptopia is already recorded as missing in `PORT_NOTES_mc1.21.1_forge.md`; Twilight Forest 1.21.1 is a NeoForge build). Could not be checked through the CurseForge API from here, so this rests on Modrinth searches and those port notes.
- Every other mod in `MOD_MATRIX.md` has `-` in the Forge 1.21.1 column (for example AE2, Undergarden, Occultism, Quark, Ex Deorum); Modrinth searches with loader forge and version 1.21.1 found no build for them either.
- Terralith and Oh The Trees You'll Grow: worldgen only.

## Judgment calls

- Left out as decoration, even though they drop themselves: shrubs, branches and beards, leaf piles, clover, ground-cover grass, bushes (BWG jacaranda, hydrangea, shrub, firecracker bush), vines and ivy, roots, sprouts, ferns, mineral clusters (prismarite, blackstone), RU redstone bud and bulb, dusktrap (hostile plant), dropleaf, hanging earlight fruit, cattail sprouts, BWG `flower_patch`, `poison_ivy`, `skyris_vine`. Plants whose only drops are wheat seeds or sticks, and all plants that drop nothing with an empty tool, are out too.
- Included although unusual: petals (BOP wildflower, BWG sakura petals, like vanilla pink petals), cacti and aloe vera on sand, glow canes on sand like sugar cane, bioshrooms (RU `*_bioshroom` saplings grow a giant mushroom; its cap blocks count as leaves and drop the mushroom itself, so these recipes yield 7 to 31 mushrooms plus the stem).
- The RU cactus flower sapling grows a saguaro cactus, not a tree: no recipe. RU joshua sapling: the leaves drop nothing, so it yields only the log.
- Some saplings grow another wood or leaf type (BOP flowering_oak yields oak saplings and apples, BWG brown_oak yields oak logs). The drops are what was actually grown.
- BOP burning_blossom, endbloom and eyebulb stay in dirt as in `common/`; new Nether plants of RU use netherrack soils like vanilla fungi.
- Not made into resource recipes: mud blocks (vanilla mud has none), coarse dirt, podzol, grass blocks and nylium (they drop dirt or stone), BOP dried_salt, thermal_calcite, flesh, BWG ice and quicksand.
- The BWG wooden-tree tag: `common/.../tags/item/wooden_tree_items.json` refers to `#skyblock_resources:biomeswebegone_saplings` (typo) while the tag file is `biomeswevegone_saplings`. Nothing in the Java code or the recipes reads `wooden_tree_items`, so it was not changed here (it is outside this task's folder rules for `common/`); worth fixing in `common/`.
